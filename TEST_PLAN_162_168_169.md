# Test plan — #162, #168, #169 (`gui_app.py` 0.31.0)

*Built 2026-10-27. Device mode only — none of this is reachable
offline. The 840 is the better device here: it is the one that
produces the renaming and renumbering.*

| | status |

## A. The reported bug — clone, deploy, verify

The whole of #168. **Device mode, 840.**

| # | do | expect |
|---|---|---|
| A1 | clone a profile, accept the suggested filename | the suggestion now looks like `CyclingRoad<Name>.fit` — prefix present, spaces as underscores (#169) |
| A2 | deploy it, eject, restart, reconnect, **Check** | **verification runs and reports no differences** |
| A3 | the message | should NOT say "couldn't automatically verify" |

**A2 is the one that matters.** Before this change it always failed
for a clone.

## B. The ordinary case must not regress

| # | do | expect |
|---|---|---|
| B1 | edit a screen on an existing profile, deploy under its own name, Check | verifies cleanly, as it always did |
| B2 | make a real change, deploy, Check | reports **that change and nothing else** |

B2 is the check that the f10 pairing did not break ordinary
reporting — it must still *find* differences, not just stop reporting
false ones.

## C. The renumbering case — what #162 is actually for

Needs a deploy the device renumbers. Per Doc rev 184 an import under a
**non-canonical filename** is the way to provoke it.

| # | do | expect |
|---|---|---|
| C1 | take a profile, change one field, export it under a deliberately odd name (`test99.fit`) | — |
| C2 | copy to `NewFiles`, restart, reconnect, **Check** | reports **only the field you changed** |
| C3 | pull the file afterwards and send it to me | I confirm the slots moved, so C2 really did exercise the pairing |

**C3 matters.** If the device happened not to renumber, C2 passes
without testing anything, and only the file shows which happened.
That is the same trap section B of the last plan fell into.

## Pass criteria

- **A2** — clone verification succeeds. The reason this release exists.
- **B2** — a real change is still reported.
- **C2 + C3** — a renumbered import reports only the real change,
  *confirmed renumbered by the file*.
- **D1** — the space becomes an underscore.

## If something looks wrong

Send me the pulled profile rather than describing it. Every useful
conclusion this week came from diffing a file; the mtime on an
840 pull is misleading (Doc rev 185), so the contents are the only
reliable witness.
